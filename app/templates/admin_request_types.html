Request types

The things people can ask IT for, listed on the request form (New starter, Software install ...). Each points at an approval group (Admin > Approval groups) whose members vote on the request before the work goes ahead. "Percent to pass" is the share of the voters that must approve, rounded up (5 voters at 60 needs 3; 100 means everyone). The request is declined as soon as that can no longer be reached (5 voters at 60: a third decline closes it). The voters are the group's members when an agent triages the request, minus the requester. "Offer a Required by date" lets the person raising the request give a date. The request is then due some days before it ("Due: days before Required by"; blank uses the setting under Admin > Settings): the SLA resolution target is the end of the Due day in the requester's time zone. "Queue lead time" (blank uses the setting) only changes the sorting: the queue ranks the request as if it were due that many days before its Due date. The defaults (team, category, impact, urgency) are optional. With all four set, a request of this type raised in the portal triages itself: it becomes a Service Request in that category and team with that priority, the SLA starts, and it goes to Awaiting approval (with an approval group) or to Open in the team queue, without waiting for an agent. With some missing it waits in New as before. Email and Teams requests are always triaged by an agent; the defaults are then filled in on the triage form when the agent picks the kind of request, and can be changed. An available type needs a group with at least one member. Switching a type off hides it from the form; tickets already raised keep it.
